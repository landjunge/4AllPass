### 4AllPass 0.1.2-rc.3 — Vorabversion / pre-release

**Deutsch**

Diese Vorabversion schließt den Maschinenzugriff, der in 0.1.2-rc.2 und älteren
Vorabversionen das echte gespeicherte Geheimnis als `access_token` an ein
verbundenes Programm weitergab. Wer dort einem Programm etwas erlaubt hat,
sollte diese Zugänge beim Anbieter ändern oder widerrufen; ein Update holt
bereits herausgegebene Kopien nicht zurück.

**Absichtliche Verhaltensänderung:** Jede Maschinenanfrage wird abgelehnt
(`handoff_unavailable`), auch nach „Erlauben“ und auch für alte Antworten.
Abläufe, die diesen Weg brauchten (zum Beispiel n8n- oder Agenten-Workflows),
erhalten eine Ablehnung. Bitte nicht umgehen, indem Passwörter in
Arbeitsbereiche von KI-Werkzeugen kopiert werden. Ein geschützter Weg, bei dem
4AllPass ein Geheimnis nutzt, ohne es herauszugeben, ist noch nicht produktiv
angeschlossen.

Weitere Korrekturen seit 0.1.2-rc.2:

- WebAuthn: exakte Herkunft und Client-Kontext werden geprüft; Geräteauswahl muss ausdrücklich passen.
- Registrierung: Mindestlänge und Offline-Sperrliste werden erzwungen.
- Desktop: native Befehle sind an ihr Fenster gebunden; lokale CSP und Netzwerkziele sind eingeschränkt; temporäre Browser-Kopien überschreiben keine Linkziele; gemessene macOS-Laufzeitausnahmen entfernt.
- Tresor-App: CSV-Import übernimmt nur vollständige Datensätze; Wiederherstellung aus dem Verlauf wird vor dem Speichern erneut geprüft; endgültiger Widerruf bleibt auch bei Metadatenfehlern erhalten; lokale Speichervorgänge warten auf ihren Abschluss.
- Server: zu große oder hängende Uploads werden sofort abgelehnt.
- Abhängigkeiten: Vite auf eine korrigierte Version aktualisiert.

Nicht enthalten: Notarisierung (macOS bleibt ad-hoc signiert, beim ersten Start
ggf. Rechtsklick → Öffnen), Windows-Signatur, unabhängiges Drittaudit,
geschützte KI-Browser-Sitzungen. Tresordaten werden nicht migriert oder
gelöscht. Lizenz unverändert: Netzwerkpunkt Personal Use License 1.0 (Deutsch
maßgeblich).

**English**

This pre-release closes the machine-access path that, in 0.1.2-rc.2 and older
previews, passed the actual stored secret to a connected program as
`access_token`. If you allowed such a request there, change or revoke those
credentials at their provider; updating does not recall copies already handed out.

**Intentional behavior change:** every machine request is denied
(`handoff_unavailable`), including after "Allow" and for stale replies.
Workflows that relied on this path (for example n8n or agent workflows) now
fail closed. Please do not work around this by copying passwords into AI tool
workspaces. A protected path in which 4AllPass uses a secret without handing it
out is not connected for production yet.

Other fixes since 0.1.2-rc.2:

- WebAuthn: exact ceremony origin and client context are verified; device selectors must match explicitly.
- Registration: minimum length and offline blocklist are enforced.
- Desktop: native commands are bound to their owning window; local CSP and network targets are constrained; temporary browser copies never overwrite link targets; measured macOS runtime exceptions removed.
- Vault app: CSV import keeps only complete records; historical recovery is re-verified before commit; hard revoke survives metadata failures; local storage writes wait for completion.
- Server: oversized or stalled uploads are rejected immediately.
- Dependencies: Vite updated to a patched version.

Not included: notarization (macOS stays ad-hoc signed; first launch may need
right-click → Open), Windows code signing, an independent third-party audit,
protected AI browser sessions. Vault data is not migrated or deleted. License
unchanged: Netzwerkpunkt Personal Use License 1.0 (German governs).
